{#- The header's two "which variant of this page am I reading" controls, side by side: version, then language. Overriding this partial is how the version selector reaches the header at all. `partials/header.html` carries no block to extend, and the only other place a template can write into the chrome is the announcement banner -- which is where this selector started. That put a second bar above a sticky header, which then scrolled away, so past the first screenful nothing on the page said which version was being read. The version list is rendered here at build time rather than by Material's own selector, which derives its base from the last path segment of the URL: under /2.5/ja/ it reads "ja" as a version name and fetches a versions.json that is not there. Its stylesheet ships with the theme whether or not that script ever runs, so the markup below is the theme's own -- md-version and its children -- and inherits the native appearance without inheriting the script. Links point at each version's root, not at the same page under another version. A page exists in one line and not another often enough -- that is what separate lines are for -- and a selector that sometimes lands on a 404 is worse than one that always lands somewhere real. With no versions in the environment -- every local build, every `mkdocs serve` -- the version control is absent and the language selector is alone, which is the header this file replaced. The language selector is unconditional because this partial only runs when the theme has alternates to offer. Everything from the marker below is a verbatim copy of partials/alternate.html as shipped by mkdocs-material 9.7.7, the version pinned in scripts/build-docs.sh. A copy is what the placement costs, so it is a copy and not a rewrite: the language routing in main.html finds a reader's explicit choice by looking for an .md-select__link carrying an hreflang, and a paraphrase that dropped either would go on rendering a selector that silently stopped remembering which language was picked. A test pins the theme version in the line above against the pin the build actually uses, so bumping the theme cannot leave this copy behind unnoticed. -#} {%- set spec = config.extra.doc_versions | default("", true) | string -%} {%- set root = config.extra.doc_site_root | default("", true) | string -%} {%- if spec and root -%} {%- set rows = [] -%} {%- for entry in spec.split(";") -%} {%- set parts = entry.split("|") -%} {%- if parts | length >= 3 and parts[0] -%} {%- set _ = rows.append(parts) -%} {%- endif -%} {%- endfor -%} {%- if rows -%} {%- set japanese = (config.theme.language | default("en", true) | string) == "ja" -%} {%- set label = "バージョン" if japanese else "Version" -%} {%- set names = namespace(here="") -%} {%- for parts in rows -%} {%- if parts[2] == "here" -%} {%- set names.here = parts[1] -%} {%- endif -%} {%- endfor -%} {#- Built on md-select, the same component the language selector below is built on, so the two controls behave identically: the list opens beneath the button, centred under it and pointed at it by the arrow the theme draws, and it closes on the same delay. md-version was the obvious component to reach for and was wrong for this position. Its list carries no `top` and no `left`, because upstream places that control at the left of the header where the static position happens to land correctly; over here it opened on top of its own button and hid the version it was showing. md-select positions its panel explicitly, so it does not depend on where in the header it sits. What is kept from md-version is the button: the label colour, the dropdown caret, and the affordance of a control whose face is a word rather than an icon. The rows are md-select__link and deliberately carry no hreflang. The language routing in main.html records a reader's choice by reading the hreflang off any clicked md-select__link, so a version row that had one would be filed as a language preference -- and the reader would be redirected to a language named after a version number from then on. A gate checks for this rather than a comment, because the attribute is the natural thing for someone to add while making the two lists look alike. -#}
