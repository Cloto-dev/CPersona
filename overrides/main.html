{% extends "base.html" %} {# Language routing for a statically hosted site. GitHub Pages cannot negotiate on Accept-Language — there is no server to read it — so a reader arriving from the README's links lands on whichever tree the link named, English, whatever they read. The hreflang alternates the i18n plugin already emits fix that for search engines; they do nothing for someone who followed a link. So the routing happens here, in the head, before the body paints, and it obeys two rules that matter more than the detection itself: * An explicit choice wins, forever. Clicking English in the language selector is a decision; a site that bounces that reader back to Japanese on the next page is broken in a way that cannot be worked around. * Redirect with location.replace, never assign. A redirect in the history stack turns the back button into a trap: back, redirect, back, redirect. Detection itself is deliberately dumb — the first entry in navigator.languages that is either Japanese or English decides, so a reader whose list is ['en-US', 'ja'] gets English and one whose list is ['ja', 'en'] gets Japanese. The destination URLs are rendered from the same per-page alternates the plugin builds the language selector from, rather than assembled here by string surgery on the path. That keeps this template from carrying a second, private theory of what the Japanese URL of a page is — the kind of duplicate that goes wrong silently the first time the URL layout changes. #} {% block extrahead %} {{ super() }} {%- set alternates = {} -%} {%- for alt in config.extra.alternate | default([], true) -%} {%- set _ = alternates.update({alt.lang: alt.link | url}) -%} {%- endfor %} {%- if alternates.en %} {%- endif %} {% endblock %}
