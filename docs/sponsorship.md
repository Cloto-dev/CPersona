# Sponsorship

CPersona is MIT-licensed. You can run it, read it, change it and redistribute
it without paying anyone, and nothing on this page changes that. If you close
this tab now, everything else on this site still applies to you in full.

Sponsorship exists because the work has costs the licence does not cover: the
hours, the machines the test suite runs on, and the time it takes to write the
pages you are reading. If CPersona has earned a place in your workflow and you
would like that to continue, you can
[sponsor Cloto-dev on GitHub](https://github.com/sponsors/Cloto-dev). One-time
and monthly are equally welcome, and neither is expected.

## What sponsorship does not buy

It is worth being explicit, because the opposite arrangement is common enough
that people reasonably assume it:

- **No feature is held back for sponsors.** There is no paid tier, no
  sponsor-only build, and no plan to add one.
- **It does not move you up the issue queue.** Issues are triaged by impact,
  reproducibility and safety — a reproducible data-loss report from someone who
  has never sponsored anything outranks a feature request from anyone.
- **It is not a support contract.** There is no response-time commitment
  attached to it, and it should not be budgeted as if there were.

One sponsorship page covers CPersona, [ClotoCore](https://github.com/Cloto-dev/ClotoCore)
and the other projects published under the same account, so sponsoring cannot
be earmarked for one of them. That is a limit of the mechanism, said plainly
rather than papered over.

## Where it goes

Development time, testing and infrastructure — including the machines that run
the embedding benchmarks — documentation, maintenance of the released lines,
and answering questions.

## Ways to help that cost nothing

For a project this size these are worth more than money, and they are listed
second only because they take longer to explain:

- **Star the repository.** It is the cheapest signal that decides whether the
  next person who needs this finds it.
- **Say which part of the setup was confusing.** A configuration problem
  mistaken for a bug means the documentation was unclear, which is a defect of
  its own — so that report is welcome even when nothing is broken.
- **File an issue with steps that reproduce it.** Reproducibility is the single
  thing that most changes how fast something gets fixed.
- **Fix a sentence in the docs**, or add the example you wished had been there.
- **Tell someone who has the problem this solves.** Most people who use
  CPersona heard about it from a person, not from a search.

## Being thanked in public

Sponsors are not listed anywhere by default. If you would like to be thanked
publicly, say so and it will be arranged with your name and link as you want
them written; if you say nothing, nothing is published. Sponsorship is visible
on GitHub's own sponsor list unless you make it private there, which is a
setting on your side rather than this project's.
